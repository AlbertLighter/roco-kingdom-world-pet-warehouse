# 放生推荐算法

## 概述

对用户拥有的所有活跃精灵（`is_active=1`），按进化链家族分组（同一精灵的不同形态合并为一个家族），在每个家族内部按规则排序，保留少数优质个体，其余标记为"建议放生"。

## 整体流程

```
所有活跃精灵 ──按 evolutionId 分组────→ 家族A, 家族B, ...
（同一进化链的不同形态合并为一个家族）      │
                          ┌──────────┴──────────┐
                          │ compute_species_     │
                          │ recommendations()    │
                          └──────────┬──────────┘
                          ┌───────────────┴───────────────┐
                          │  每个精灵 → is_recommended?    │
                          │  + reasons (放生原因文案)       │
                          └───────────────────────────────┘
```

**分组依据：** 使用 `evolutionId`（游戏配置中的 `pet_evolution_id`）作为家族标识符。
- 同一进化链的不同形态（如奇丽草 stage1、奇丽叶 stage2、奇丽花 stage3）共享相同的 `evolutionId`，合并为一个家族统一计算。
- 无进化链的品种（`evolutionId = []`）各自作为独立家族。
- 家族名称取 stage=1（初始形态）的名称作为代表名。`species_name: "奇丽草"` 代表整个奇丽家族。
- 响应中附带 `member_species` 字段列出族内所有形态：`[{base_id, name, stage}, ...]`。

## 决策顺序（8 步淘汰制）

对每个品种内的所有精灵，按以下优先级依次处理。**一旦被标记为"保留"，不再参与后续排序。**

| 步骤 | 规则 | 保留策略 | 其余处理 |
|------|------|----------|----------|
| **1** | `mutation ∈ {1, 8, 9}`（异色/炫彩/异色炫彩） | **全部保留** | — |
| **2** | `talent_skill = 50001`（特长：慈悲为怀） | **全部保留** | — |
| **3** | `talent_skill = 402`（特长：同乘） | **只保留最优 1 只**（按 `rank_ride_pets` 排序） | 推荐放生，理由："同乘特长，但有更好的同乘个体" |
| **4** | `talent_skill = 1001`（特长：爱分享） | **只保留最优 1 只**（按天赋总和降序） | 推荐放生，理由："爱分享特长，但有更好的爱分享个体" |
| **5** | `talent_skill = 401`（特长：疾行） | **只保留最优 1 只**（按 `rank_ride_pets` 排序，与同乘同一逻辑） | 推荐放生，理由："疾行特长，但有更好的疾行个体" |
| **6** | `gender = 2`（雌性） | 按体型降序，**保留体型最大的母方 1 只**用于繁育 | — |
| **7** | 普通精灵（`talent_skill = 0`） | 按 `compute_pet_score` 评分降序，**保留前 `keep_count` 只**（默认 3） | 推荐放生，理由：评分较低 / 超出保底数量 |
| **8** | 其余（极少情况） | — | 推荐放生，理由："综合评分较低" |

## 评分公式 `compute_pet_score`（满分 100）

```
score = talent_score + rank_score + size_score + nature_score + skill_bonus
```

| 维度 | 满分 | 计算方式 |
|------|------|----------|
| 天赋分 `talent_score` | **10** | `六项天赋总和 ÷ 186 × 10`（上限 10）<br>186 是六项天赋各自满值之和（6 × 31） |
| 天赋等级分 `rank_score` | **20** | 普通(1)=0, 良好(2)=7, 优秀(3)=13, 极品(4)=20 |
| 体型分 `size_score` | **30** | 身高体重在该品种范围内百分位均值 × 30<br>`_get_size_score()` = `(height_pct + weight_pct) / 2` |
| 性格分 `nature_score` | **30** | 未配置偏好 = 15<br>匹配任一偏好 = 30<br>不匹配 = 10 |
| 特长加分 `skill_bonus` | **10** | 无特长 = 0<br>同乘 / 爱分享 / 疾行 = 7<br>慈悲为怀 = 10 |

> **分数越低 → 越建议放生。**

## 同乘/疾行排序 `rank_ride_pets`

同乘和疾行精灵的优先级分数独立计算，不适用通用评分（共用同一排序函数）：

```
_ride_score = speed_talent × 3
            + (加速度性格 ? 10 : 0)
            + 天赋等级加分 (普通0, 良好2, 优秀4, 极品6)
            + 体型微调 (height + weight/1000) / 10000
```

按 `_ride_score` **降序**，第一名保留，其余推荐放生。

## 放生原因文案

定义在 `_RELEASE_REASON_TEMPLATES`（第 772 行）：

| 场景 | 文案 |
|------|------|
| mutation 保留 | 异色/炫彩变异 |
| 慈悲为怀保留 | 特长：慈悲为怀 |
| 同乘保留（最优） | 同乘优选保留 |
| 同乘被放生 | 同乘特长，但有更好的同乘个体 |
| 爱分享保留（最优） | 爱分享优选保留 |
| 爱分享被放生 | 爱分享特长，但有更好的爱分享个体 |
| 疾行保留（最优） | 疾行优选保留 |
| 疾行被放生 | 疾行特长，但有更好的疾行个体 |
| 无特长 + 天赋总和 < 50 | 无特长，天赋总和较低 |
| 超出保留名额 | 已超出该品种最少保留数量 |
| 兜底 | 综合评分较低 |

> 如果精灵有多个理由（如同乘被放生 + 性格不匹配），会叠加返回多条文案。

## 用户可配置项

通过 `species_preferences` 表配置，前端 UI 在"品种偏好设置"中修改：

| 字段 | 含义 | 默认值 |
|------|------|--------|
| `keep_count` | 每个家族至少保留几只普通精灵 | `3` |
| `preferred_nature_ids` | 该家族偏好的性格 ID 列表（可多选） | `[]`（不指定） |

不指定偏好性格时，性格分固定为 15（满分 30 的一半）；指定一个或多个后，精灵性格匹配列表中任一性格即得 30 分，全不匹配得 10 分。

**参数：**

| 参数 | 类型 | 默认 | 范围 | 说明 |
|------|------|------|------|------|
| `page` | int | 1 | ≥ 1 | 页码 |
| `page_size` | int | 20 | 1~5000 | 每页品种数 |
| `min_score` | float | null | — | 最低评分过滤（暂未实装） |
| `species_id` | int | null | — | 只查某个品种 |

### `GET /api/release_summary`

首页概览用，粗略估算（不含品种偏好配置）：
